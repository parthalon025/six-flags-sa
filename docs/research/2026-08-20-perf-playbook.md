# Train H Performance Playbook — Baking, Banding, and the Zero-Blank-Tile Contract

*Companion perf spec for the painted-map + live-overlay stack (MapLibre GL, 3-band raster pyramid, PMTiles CDN streaming, offline venue pack). Every claim below is traced to Lens A (90s game dev) or Lens B (Google Maps / MapLibre / Mapbox GL) research dumps — no outside recall.*

> **Amended 2026-08-20 by [ADR-0021](../adr/0021-zoomable-worlds-revised.md).** Automatic on-wear pyramid sync is withdrawn, so rows 2 and 14 and the sync half of row 12 lapse with it, as does the sync-under-load gate row. Band units are restated in ground sample distance (2.4 / 0.6 / 0.15 m/px) on power-of-two steps. The zero-blank-tiles gate drops from correctness to polish: Truth ships offline, so a missing tile is ugly, not wrong. Every row marked **Lapsed** below stays in the table as the record of why it existed.

---

## 1. The shared philosophy: spend offline compute to save runtime compute

Both eras converge on one throughline, and Train H already embodies it in its foundational asset pipeline.

**Lens A's version:** BSP tree construction was "precomputed offline during level compilation" (DoomWiki, "BSP (node builder)"); Quake's PVS was "requires the world to be static," trading flexibility for large fixed runtime wins (Abrash, Dr. Dobb's PVS article); Quake's lightmaps were baked once by `light.exe` and reused as a cached buffer at runtime rather than lit per-pixel (Abrash, *Quake's Lighting Model: Surface Caching*); mipmaps are "a chain of progressively half-sized, prefiltered texture images" computed once (Lance Williams, "Pyramidal Parametrics," 1983); Crash Bandicoot's NPT tool was a workstation-run "expert system" that laid out CD data offline so the PS1's runtime CPU only had to page prebuilt 64KB chunks (Andy Gavin, *Crash Bandicoot — Teaching an Old Dog New Bits, part 3*). Lens A's own synthesis (item 13) names this pattern explicitly across items 2, 3, 6, 8, 9.

**Lens B's version:** the entire vector-tile pipeline exists to move "efficient delivery of small chunks of geodata" work off the runtime path (Mapbox Vector Tile spec), and Tippecanoe's per-zoom simplification tolerance is a *build-time* generalization budget, not a runtime cost (`tippecanoe` README, cited via Lens B §4).

**Train H's version:** the 3-band raster pyramid (overview 2.4 m/px, mid 0.6 m/px, close 0.15 m/px) is *already* a baked-lightmap-style artifact — painted once at build time, shipped as static pixels, selected at runtime by zoom exactly the way a mip chain is selected by texel/pixel ratio (Lens A #6; Lens B §1 tile pyramid architecture). The playbook below is not "add 90s tricks to a modern map engine" — it's "extend the baking discipline the factory already uses to the remaining runtime-computed surfaces: tile selection, overlay compositing, cache eviction, and skin-wear sync." Every row is graded against the owner's rule: **an optimization that is invisible in the final frame is in-scope; an optimization that changes what the player sees is not**, mirroring Abrash's own framing of dirty-rectangle blitting as "pixel-identical output... pure bandwidth optimization" (Lens A #10) and mipmapping as "explicitly ANTI-degradation" (Lens A #6).

## 2. Technique-by-technique playbook

| # | Technique | Precedent & source | Exact application in the H stack | Status |
|---|---|---|---|---|
| 1 | **Baked band = mip level, selected not computed** | Quake lightmaps baked by `light.exe`, reused at runtime (Abrash, *Quake's Lighting Model*); mipmapping as precomputed prefiltered pyramid (Lance Williams 1983; N64 hardware LOD, Lens A #6); Google's tile-pyramid model (Lens B §1) | Keep the 3 raster bands (2.4 / 0.6 / 0.15 m/px, power-of-two steps) as fixed offline bakes, selected by MapLibre zoom exactly as a mip level is selected by texel/pixel ratio — never recompute a band at runtime. `tileSize` stays MapLibre's 512px default per source (Lens B §1) so viewport coverage needs the documented "2-4 tiles, sometimes one" (Mapbox "10 Years of Mapbox GL"). | **Build-time default** — already core to Train H's asset pipeline |
| 2 | **Skin-wear sync ships a bank-swap diff, not a full re-fetch** | NES CHR banking: MMC3 swaps 8/4KB tile banks sharing the same tile IDs for "zero added draw cost" animation (Lens A #1, SMB2/3); Mapbox offline dedup: shared tile packs across regions are stored once and ref-counted, style/font packs cached separately from tile packs (Lens B §13) | Background full-pyramid sync on skin wear diffs against the tile-ID scheme already shared across skins (same coordinate grid, different pixels) and re-downloads only changed tile entries — a "bank swap," not a fresh pyramid. Bind each skin's tile pack to the venue's style pack as separate, independently-cacheable artifacts (Lens B §13's tileset-descriptor pattern). | **Lapsed** — on-wear sync withdrawn (ADR-0021 clause 5); nothing bulk-downloads a pyramid to diff |
| 3 | **Pitched-camera viewport culling** | Quake PVS caps drawable polygons regardless of scene complexity (Abrash, Dr. Dobb's); Thief's portal/cell traversal culls off-corridor rooms (Sean Barrett, *Thief Rendering*, Lens A #4); Mapbox GL JS v2.1.1 pitched-tile loading "reduces the number of tiles in view by up to 20%" with "very little visual difference" (Lens B §6) | Train H's pitch-eases-with-zoom camera rides MapLibre's built-in pitched-horizon culling as-is — do not disable or override the horizon-line computation. This is the single largest tile-count win available and costs nothing visually per the cited Mapbox measurement. | **Build-time default** — verify it isn't inadvertently disabled by camera-ease custom code |
| 4 | **Prefetch rings ahead of the camera** | Crash Bandicoot's NPT paged 64KB chunks in "timed so data arrived before Crash reached that part of the level" (Andy Gavin, Lens A #8); Jak and Daxter streamed "without stalling gameplay or causing ugly visual popping" (Naughty Dog postmortem, Lens A #9); `getPrefetchZoomDelta` (default 4) and `flyTo({preload:true})` defer camera animation until path tiles are loaded (Lens B §6) | Enable coarse-band prefetch (show overview band as a ring ahead of the viewport) plus `preload`-style camera-move prefetching for any guided-tour/waypoint camera moves, so PMTiles range requests for mid/close bands are in flight before the pitch-ease arrives there. Directly targets the **zero-blank-tiles** gate. | **Build-time default** |
| 5 | **Parent-band placeholder + crossfade, not a pop** | Insomniac's Spyro LOD: "details smoothly emerge as you get closer" instead of fog-hiding (secondary-sourced retrospectives, Lens A #7 — flagged weaker-sourced); Mapbox GL JS retains a loaded parent tile, displays it scaled under the child tile, then cross-fades (`raster-fade-duration`), and reuses overzoomed data past `maxzoom` (Lens B §5) | When close-band PMTiles range data hasn't arrived yet, MapLibre falls back to the scaled mid-band (or mid falls back to overview) as a parent placeholder and cross-fades in the true band — never a hard cut, never a blank cell. This is the mechanism that actually satisfies "zero blank tiles during normal pan" without visual popping. | **Build-time default** |
| 6 | **Worker-thread PMTiles decode** | Volkswagen Infotainment case: worker-offloaded tile-parse/label-placement keeps 60fps on the map while the main thread handles CAN-bus telemetry (Lens B §10/§11); general architecture: "heavy lifting... off-loaded to web workers, keeping the main thread free" | PMTiles HTTP range-request parsing and tile-buffer construction for overview/close bands run in a Web Worker, matching MapLibre's own architecture, so the main thread stays free for draw calls under the **4x CPU throttle** gate. | **Build-time default** |
| 7 | **Cancel stale in-flight tile work mid-gesture** | Quake PVS avoids "worst-case overdraw of ten times or more" by bounding drawable work per frame (Abrash, Lens A #3); `cancelPendingTiles` option + AbortController-driven fetch cancellation tear down both the network request and in-flight worker parse together when a tile becomes irrelevant (Lens B §6/§11) | Enable `cancelPendingTiles` so a fast pan/zoom under 4x throttle doesn't let stale-zoom tile fetches starve the current viewport's real requests — same "bound the worst case" spirit as PVS. | **Build-time default** |
| 8 | **Explicit LRU tile-cache budget, sized for the low-end floor** | Mapbox GL JS `TileCache` is a textbook LRU, default sized at "50MB / (100KB/tile) ~= 500 tiles" (Lens B §7); known failure mode: decoded raster-array buffers can leak past the nominal LRU limit (mapbox-gl-js issue #13688, Lens B §7) | Define an explicit in-memory tile-cache budget tuned to the **30fps low-end floor** device class (not the library default), and specifically stress-test the background full-pyramid sync path against issue #13688-style leaks — a sync that decodes a whole new pyramid while the old one is still cached is exactly the accumulation pattern that bug describes. | **Adopt-on-trigger** — still live for viewport streaming: an explicit cache budget tuned to the low-end floor. The sync-decode leak stress test lapses with on-wear sync (ADR-0021 clause 5) |
| 9 | **Overlay updates touch only changed buffer regions** | Abrash's dirty-rectangle animation: track bounding rects of only what changed, blit only those regions — "pixel-identical output... pure bandwidth optimization" (Lens A #10); Mapbox uploads per-symbol opacity buffers (current/target) and lets the shader interpolate, not a CPU re-render loop (Lens B §8) | Party-dot, quest-node, and route updates diff against the previous frame's symbol/line data and update only changed GPU buffers, never trigger a full overlay-layer rebuild per tick — same guarantee as dirty rectangles: pixel-identical result, cheaper path. | **Build-time default** |
| 10 | **GPU-side global collision + time-based fade for overlay icons** | Mapbox GL JS PR #5150: moved collision detection to a single global viewport grid (25px cells, tuned from 15–40px), frame cost held near baseline via per-bucket pause logic (5.3ms→6ms→back down); fade is "based on time elapsed since collision occurred," not zoom level, synchronized via `CrossTileSymbolIndex` so a label doesn't re-fade crossing a tile/zoom boundary (Lens B §8) | Quest-node and party-dot symbol layers use MapLibre's built-in global collision detection and time-based fade rather than custom per-band logic — this specifically prevents icons from popping or re-fading as the camera crosses the overview→mid→close band boundary, which a naive zoom-triggered fade would visibly do. | **Build-time default** |
| 11 | **SDF icon atlas, shelf-packed** | Sprite/polygon batching to minimize draw-call state switches, corroborated by analogy to Quake's surface-cache architecture (Lens A #12, flagged as not period-primary-sourced); Mapbox glyphs are SDF, packed via `shelf-pack`'s "Shelf Best Height Fit" heuristic, refcounted so unused icons can be evicted (Lens B §9) | Quest-node icons, route markers, and party-dot glyphs pack into one SDF atlas via shelf-pack, batching overlay draw calls and enabling resolution-independent scaling/halos without re-rasterizing (`smoothstep` edge antialiasing, Lens B §9) — sharp icon edges at any zoom band, matching the mipmap ethos of anti-aliasing rather than accepting it. | **Build-time default** |
| 12 | **Render-on-demand; schedule sync at idle, never mid-gesture** | Mapbox's modular-architecture rework cut time-to-idle up to 50% and reduced CPU/battery draw (Lens B §10); MapLibre's `idle` event fires when "all requested tiles have loaded and there are no active camera transitions"; shader precompilation is deliberately deferred to run after `idle` to avoid a jank spike (Lens B §10) | Pause the render loop when camera and overlay are static (a player standing still reading a quest node), and gate the start of the background full-pyramid sync job on the `idle` event — never kick it off mid-pan/pitch, protecting the 4x-throttle 60fps gate from a sync-induced frame spike. | **Split** — render-on-demand stands as a build-time default (it is the battery win when the screen is on). The `idle`-gated sync scheduling lapses with on-wear sync (ADR-0021 clause 5) |
| 13 | **WebP encoding for baked raster bands** | WebP lossy is 25–34% smaller than JPEG "at equivalent visual quality," WebP lossless ~26% smaller than PNG (developers.google.com/speed/webp, cited Lens B §12); Cesium reports "3D tilesets using WebP finish loading ~36% faster than the JPEG version" (Lens B §12) | Encode the overview/mid/close painted bands (and their PMTiles payloads) as WebP at build time instead of PNG/JPEG — a pure bandwidth win at the cited "equivalent visual quality," directly feeding the **≤2s warm / ≤4s cold time-to-first-map** gate. | **Build-time default** |
| 14 | **Offline pack dedup with an explicit ceiling** | Mapbox OfflineManager binds a region's tile pack to a style pack as independently-cacheable artifacts; overlapping regions reuse shared tile packs "conserving network traffic and disk space" rather than duplicating; a hard documented ceiling caps "cumulative... unique map tile packs" at 750 (Lens B §13) | The mid-band offline venue pack and the CDN-streamed overview/close bands are independently-cacheable artifacts (per row 2/6). When skin-wear sync runs, previously-downloaded shared tiles are reused/ref-counted, not re-pulled. Define an explicit per-device storage ceiling for Train H analogous to Mapbox's 750-pack limit, so sync has a documented refusal behavior instead of unbounded growth. | **Lapsed** — on-wear sync withdrawn (ADR-0021 clause 5). An explicit storage ceiling returns if the opt-in offline download ships |

## 4. Anti-patterns to refuse

Techniques present in the research dumps that **do** trade away visual quality for speed. The owner's rule refuses these outright for Train H, even where the source material presents them as legitimate tradeoffs in their own context.

- **`raster-fade-duration: 0`.** Cited by MapLibre's own perf docs as one of three recommended production tuning flags "to eliminate label/tile cross-fade overhead" (Lens B §14). Setting it to zero removes the parent→child crossfade that row 5 relies on — tiles pop in abruptly instead of fading. That is a visible frame-to-frame change in what the player sees, and it directly undermines the zero-blank-tiles gate's *intent* (smooth transitions, not just "something is drawn"). **Refused**; keep fade duration at a tuned non-zero value.
- **Fog/blur to mask short draw distance or streaming pop-in.** Lens A #7 explicitly frames Spyro's LOD system as eliminating "the dark fog most PS1 titles used to hide short draw distance," and Jak and Daxter's streaming was engineered specifically to avoid "ugly visual popping" rather than paper over it (Lens A #9). Using fog, blur, or a dimming overlay to hide unloaded pyramid bands or overlay pop-in is the exact failure mode both precedents were built to avoid. **Refused.**
- **Increasing Tippecanoe/GeoJSON `tolerance` beyond default on live overlay geometry.** Per-zoom simplification (Lens B §4) is a legitimate *build-time* budget for background vector data — Tippecanoe's own docs note tolerance-driven size cuts of up to 40% depending on vertex density. But quest routes and party-position lines are live gameplay data, not backdrop; coarsening them to save bytes is a direct, player-visible fidelity loss on the one layer where precision matters most. **Refused for the overlay layer**; acceptable only for background vector data Train H does not currently ship.
- **Lossy compression on the overlay icon/glyph atlas.** WebP lossy at "equivalent visual quality" (Lens B §12) is approved for the baked painted-map raster bands (row 13), where it matches the source's own quality claim. It is not approved for the SDF icon atlas (row 11): compression artifacts on sharp glyph edges would visibly degrade quest-node and party-dot icons, contradicting the entire SDF rationale of "antialiased text/icons at any zoom without re-rasterizing." **Refused for the icon atlas**; keep it lossless/vector (SDF).
- **Hard-snapping between pyramid bands without a mip-style blend.** Mipmapping's "entire purpose is suppressing aliasing/moiré/shimmering... that would otherwise look worse without it" (Lens A #6). Using the 3-band pyramid as an excuse to hard-cut between overview/mid/close on zoom crossing (skipping the parent-placeholder crossfade in row 5) reintroduces the exact popping/aliasing artifact mipmapping exists to prevent. **Refused**; band transitions must always cross-fade.
